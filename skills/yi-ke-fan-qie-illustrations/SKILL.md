# 一颗番茄·正文配图

把文章里的判断、步骤、状态或隐喻，转成有“一颗番茄”识别度的中文正文配图。这个 Skill 继承 Ian 小黑的留白、动作隐喻和克制批注方法，但不使用小黑角色，也不复刻其旧案例。

## 模式路由

先判断内容需要什么，不把四种画面语法混在一张图里：

| 模式 | 适用内容 | 读取 |
|---|---|---|
| A 番茄女孩怪诞隐喻 | 个人经验、判断、方法论、状态转变；默认模式 | `references/mode-character-metaphor.md` |
| B 极简线条隐喻 | 抽象观点、认知转折、金句 | `references/mode-minimal-line.md` |
| C 步骤解释 | 工作流、框架、清单、教程 | `references/mode-step-explainer.md` |
| D 实物微人 | 品牌封面、生活观察、物件驱动内容 | `references/mode-object-doodle.md` |

用户指定模式时服从用户。未指定时，根据内容目的选择；不要因为角色可用就强行画角色。

用于手机观看的 HTML 录屏、竖屏知识内容，或用户反馈角色/图内字太小时，另读 `references/mobile-knowledge.md`。这是展示尺寸的适配，不是第五套画风；不改变模式 B/D 的微型角色用途。

## 开始前读取

任何生成任务都读 `references/shared-mechanisms.md` 和所选模式文件。需要写完整生图提示词时再读 `references/prompt-template.md`。生成后按 `references/qa-checklist.md` 检查。遇到重复失败或用户明确反馈时读写 `references/failure-log.md`。

角色出现时，必须上传 `assets/character-master-v2.png` 作为身份参考。如需额外视觉参考，由使用者提供并确认使用权；只参考留白、材质和融合密度，不照搬构图。

## 工作流

1. 提炼一张图唯一要表达的判断，并找出内容中的张力，如混乱/清晰、多/一、卡住/流动。
2. 把抽象概念翻译成一个物理动作，再选择一种低科技物件或真实物件承载动作。
3. 选择模式并加载对应参考。先锁识别锚点，再设计可变的比喻、动作和构图。
4. 用户只要策略时，给简短 shot list；用户要求生成时，直接调用可用的图像生成工具，每张图单独生成。
5. 多页任务先出页面大纲；方向尚未锁定时只生成封面和第一页。方向确认后再继续，避免整批返工。
6. 生成后做视觉和文件检查。差一点时只改一个变量，在选中版本上迭代，不推倒重来。

## 共同铁律

- 一图一意；主体承担动作，不站旁边解释。
- 优先纯白、不透明背景；至少 35% 留白。
- 文字越少越好。非封面单处中文通常不超过 6 字；要求准确时逐字校对。
- 正文插图默认 16:9 横版；封面、竖图或平台比例以用户要求为准，并同时写方向和具体尺寸。
- 不出现小黑、第二套人物 IP 或无关吉祥物。
- 不照搬原小黑案例、文章示例或参考图构图；参考只提供规则与密度。
- 不使用“高级感、文艺、手绘感”等空泛审美词代替可执行动作和数字。

## 维护纪律

- 锚点和变量分开维护；跨模式重复规则只写在 `shared-mechanisms.md`。
- 用户反馈先记录现象，再翻译成数字、动作或禁止项；不要归因成“模型不行”。
- 每轮只改一处，改完用真实样本复测。一次改动超过现有内容一半时，优先重做对应文件而非叠补丁。
- 只把真实出现并能改变下次行为的失败写入失败记录。

## 保存

项目内生成时，保存到 `assets/yi-ke-fan-qie-illustrations/<slug>/`，按顺序命名。不要覆盖旧版本。交付时说明所用模式、用途、保存路径、提示词摘要和仍需人工判断的地方。
