# 手机知识图与 HTML 录屏适配

用于手机观看的知识图、竖屏 HTML 中的配图，以及“人物或图内字太小”的反馈。先遵守所选画面模式，再调整最终显示尺寸；不把这些建议套到有意使用微人的抽象隐喻或实物模式。

## 先看展示框，而不是只看原图

- 确认插图是整屏画面还是 HTML 中的一个区域。整页是 3:4，不代表嵌图也要 3:4；角色与两个短标签的局部解释图可先试 4:3 或接近方形。
- 已有横图放进竖屏后太小时，先缩短横向物件、减少无意义折叠或重复段，让动作集中；不要只提高文件分辨率，也不要无条件裁掉留白。
- 按最终约 375 像素宽度检查。核心标签可先以显示后约 18 像素为目标，根据字形与语境调整。角色的手、接触点和关键身份特征应可辨认，不能只在放大原图时成立。
- 比例是构图变量。画面可以有足够留白，同时让角色和标签更大；不要把“留白至少 35%”误解为所有主体都必须微小。

## 自有角色替代小黑时

继承小黑的动作隐喻、白底、少量批注，不保留黑色小人的外形。使用现有角色母版与“知识形象”；不把完整站姿头像贴到图边，也不同时出现两套 IP。

先保证角色实际参与动作，再处理身份细节。额心痣、卷发轮廓、番茄徽章、服装与红鞋保留；细节密度按 `shared-mechanisms.md` 的知识形象规则简化。若用户在本轮提供新的身份参考，优先遵从本轮参考，不擅自把一次试图替换成永久母版。

## 图像和准确文字分工

- 图内只放简短概念词，逐字校对；长 JD、来源、数字口径留在 HTML 文字层，便于阅读和修改。
- 手写规则只作用于生成图中的文字和短批注，不要求 HTML 正文也用手写体。
- 先产出一张动作样张，保留此前版本；用户确认身份与密度后再扩展系列。不要自动把一次岗位纸条案例固化成所有内容的默认构图。
- 图片缩略检查、HTML 实际排版检查、用户偏好确认分开报告；一种检查不能替代另外两种。
